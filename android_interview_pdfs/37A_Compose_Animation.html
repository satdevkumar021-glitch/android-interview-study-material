37A — Jetpack Compose Animation

Complete guide to Compose animation APIs: animateAsState, updateTransition, AnimatedVisibility, AnimatedContent, rememberInfiniteTransition, and Motion.

ID: 37A ⭐ Tier 1 — Highest Priority
🔍
1. Overview

Why Compose Animation is Fundamentally Different

In the legacy View system, animations relied on imperative property manipulators like ObjectAnimator, ValueAnimator, or static XML files in res/anim. These animators directly mutated View properties over time, often out of sync with business state and prone to memory leaks if listeners were not cleaned up.

Jetpack Compose replaces this with a declarative, state-driven model. UI in Compose is a pure function of state: UI = f(State). When state changes from value A to value B, Compose animation APIs intercept that transition and generate a stream of intermediate interpolated values over time, driving smooth frame-by-frame recompositions or draw invalidations automatically.

Two Architectural Tiers

Compose animation APIs are split into two primary layers based on abstraction and control:

  • High-Level APIs: Pre-packaged composables and modifiers for structural layout transitions. These include AnimatedVisibility (enter/exit layout nodes), AnimatedContent (content swaps), Crossfade, and the Modifier.animateContentSize() modifier.
  • Low-Level APIs: Value-interpolation primitives for custom parameters. These include animate*AsState (fire-and-forget single value), updateTransition (synchronized multi-property state machines), Animatable (coroutine-based imperative control with gestures/cancellation), and rememberInfiniteTransition (continuous repeating cycles).

What Problem It Solves

  • Declarative Consistency: Animations are tied directly to state — no detached animators mutating UI nodes out-of-band.
  • Lifecycle & Coroutine Safety: Animations automatically respect composable lifecycles, cancel on disposal, and clean up coroutine scopes without manual listener detachments.
  • Interruptibility: Compose handles interrupted target states seamlessly (e.g. reversing mid-flight) using physics-based velocity tracking rather than jarring resets.
Senior Mental Model
Never "run" an animation imperatively in Compose. Instead, describe the target state and provide an AnimationSpec. Compose calculates the delta, tracks velocity, and manages the interpolation loop within the snapshot state system.

2. How It Works

High-Level Animation APIs

1. AnimatedVisibility

AnimatedVisibility(
    visible = isVisible,
    enter = fadeIn(animationSpec = tween(300)) + expandVertically(),
    exit = fadeOut() + shrinkVertically()
) {
    BannerCard()
}

Animates the appearance and disappearance of composable content. It inserts and removes elements from the composition tree while coordinating custom enter/exit transitions (such as slideIn, expandIn, scaleIn, fadeIn).

2. AnimatedContent

AnimatedContent(
    targetState = selectedTab,
    transitionSpec = {
        if (targetState > initialState) {
            slideInHorizontally { width -> width } + fadeIn() togetherWith
                slideOutHorizontally { width -> -width } + fadeOut()
        } else {
            slideInHorizontally { width -> -width } + fadeIn() togetherWith
                slideOutHorizontally { width -> width } + fadeOut()
        }
    },
    label = "tab_content_animation"
) { tab ->
    TabScreen(tab)
}

Seamlessly transitions between different composables as state changes, providing coordinated entry and exit specs with size transforms.

3. Modifier.animateContentSize()

Column(
    modifier = Modifier
        .animateContentSize(
            animationSpec = spring(
                dampingRatio = Spring.DampingRatioLowBouncy,
                stiffness = Spring.StiffnessLow
            )
        )
) {
    Text(text = description, maxLines = if (expanded) Int.MAX_VALUE else 2)
}

Modifier that listens to internal layout measurement changes and animates bounds changes smoothly without requiring explicit height math.

Low-Level Animation APIs

1. animate*AsState

val alpha: Float by animateFloatAsState(
    targetValue = if (enabled) 1f else 0.38f,
    animationSpec = tween(durationMillis = 250),
    label = "button_alpha"
)
val elevation: Dp by animateDpAsState(
    targetValue = if (isPressed) 8.dp else 2.dp,
    label = "card_elevation"
)

The simplest way to animate a single value (Float, Dp, Color, Offset, Int, Rect). Returns a State<T> that continuously recomposes/invalidates reading scopes with interpolated values until reaching the target.

2. updateTransition

val transition = updateTransition(targetState = buttonState, label = "box_state_transition")

val scale by transition.animateFloat(label = "scale") { state ->
    when (state) {
        BoxState.Collapsed -> 0.8f
        BoxState.Expanded -> 1.2f
    }
}
val cornerRadius by transition.animateDp(label = "corner_radius") { state ->
    when (state) {
        BoxState.Collapsed -> 4.dp
        BoxState.Expanded -> 24.dp
    }
}

Manages multiple animated properties derived from a single state machine. Keeps all properties perfectly synchronized during state switches, reversals, and inspectable in Android Studio Animation Preview.

3. Animatable

val offset = remember { Animatable(0f) }

LaunchedEffect(trigger) {
    offset.animateTo(
        targetValue = 300f,
        animationSpec = spring(dampingRatio = Spring.DampingRatioHighBouncy)
    )
}

Coroutine-based value holder supporting imperative fine-grained control: animateTo, snapTo, velocity inheritance, and gesture-driven flings.

4. rememberInfiniteTransition

val infiniteTransition = rememberInfiniteTransition(label = "radar_pulse")
val radius by infiniteTransition.animateFloat(
    initialValue = 20f,
    targetValue = 100f,
    animationSpec = infiniteRepeatable(
        animation = tween(1500, easing = LinearEasing),
        repeatMode = RepeatMode.Restart
    ),
    label = "pulse_radius"
)

Manages non-stop repeating animations like pulsing badges, radar waves, and loading shimmers.

AnimationSpec Ecosystem

AnimationSpecDescriptionUse Case
spring(dampingRatio, stiffness) Physics-based mass-spring simulation; natural, velocity-preserving, no fixed duration. Touch interactions, interactive gestures, button presses (default in Compose).
tween(durationMillis, delay, easing) Time-based duration with easing curves (FastOutSlowInEasing, LinearOutSlowInEasing). Alpha fades, structural transitions with strict timing contracts.
keyframes { durationMillis = 500; 0f at 0; 0.8f at 200 with FastOutSlowInEasing } Multi-point timeline curves with custom per-segment easings. Multi-stage choreography, complex geometric shakes/wiggles.
snap(delayMillis) Instant value shift after optional delay. Resetting state immediately or testing zero-animation modes.
repeatable / infiniteRepeatable Loops a child spec for count or infinitely (RepeatMode.Restart or Reverse). Loaders, background ambient effects, spinners.

Compose Animation Architecture

State Change → animate*AsState → AnimationSpec (tween/spring/keyframes) → recomposition with interpolated value → UI update updateTransition → multiple child animations → synchronized state machine

3. Why and When to Use It

API Selection Decision Matrix

RequirementRecommended APIReason
Show / hide composables conditionallyAnimatedVisibilityHandles enter/exit layout tree inclusion, measure, clip, and fade automatically.
Morph or crossfade full screen/state contentAnimatedContent / CrossfadeCoordinates entry of new content while animating away previous content.
Animate single numeric or color propertyanimate*AsStateLowest friction; declarative fire-and-forget state interpolation.
Coordinate multiple properties from one stateupdateTransitionAvoids desynchronization; guarantees all sub-properties evaluate atomically.
Continuous loading shimmer, rotation, pulserememberInfiniteTransitionLifecycle-bound endless loop that halts when composable exits composition.
Swipe-to-dismiss, fling, drag gesturesAnimatableSuspends in coroutine; allows imperative snapTo during drag and animateTo on release.
Container expands when text or child growsModifier.animateContentSize()Zero boilerplate; automatic layout bounds animation.

When NOT to Animate

Avoid Animation Here
  • Purely Functional State Swaps: Instant critical data updates (e.g. error alerts, emergency security prompts) where animation latency slows user safety.
  • Every List Item Scroll: Triggering heavy layout animations on fast scrolling LazyColumn causes frame drops and jank.
  • Accessibility "Reduce Motion" Active: When users have enabled reduced motion in OS accessibility settings, heavy scale/slide animations must fall back to snap or subtle alpha fades.

4. Production Example
Scenario
E-commerce app: Animated Add-to-Cart CTA button transitioning smoothly between Idle, Loading, and Success states with physics spring width and color changes, combined with an infinite loading shimmer box.

Complete Implementation

import androidx.compose.animation.*
import androidx.compose.animation.core.*
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.shape.RoundedCornerShape
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Check
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Brush
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.dp
import kotlinx.coroutines.delay

// State for animation
enum class CartButtonState { Idle, Loading, Success }

@Composable
fun AddToCartButton(
    onAddToCart: () -> Unit,
    modifier: Modifier = Modifier
) {
    var buttonState by remember { mutableStateOf(CartButtonState.Idle) }
    val transition = updateTransition(targetState = buttonState, label = "cart_button")

    val buttonWidth by transition.animateDp(
        label = "width",
        transitionSpec = { spring(dampingRatio = Spring.DampingRatioMediumBouncy) }
    ) { state ->
        when (state) {
            CartButtonState.Idle -> 160.dp
            CartButtonState.Loading -> 56.dp
            CartButtonState.Success -> 56.dp
        }
    }

    val buttonColor by transition.animateColor(label = "color") { state ->
        when (state) {
            CartButtonState.Idle -> MaterialTheme.colorScheme.primary
            CartButtonState.Loading -> MaterialTheme.colorScheme.surfaceVariant
            CartButtonState.Success -> Color(0xFF3ECF8E)
        }
    }

    Button(
        onClick = {
            if (buttonState == CartButtonState.Idle) {
                buttonState = CartButtonState.Loading
                onAddToCart() // ViewModel handles actual API call
            }
        },
        modifier = modifier.width(buttonWidth),
        colors = ButtonDefaults.buttonColors(containerColor = buttonColor),
        shape = RoundedCornerShape(50)
    ) {
        transition.AnimatedContent { state ->
            when (state) {
                CartButtonState.Idle -> Text("Add to Cart")
                CartButtonState.Loading -> CircularProgressIndicator(
                    modifier = Modifier.size(20.dp),
                    strokeWidth = 2.dp,
                    color = MaterialTheme.colorScheme.onSurfaceVariant
                )
                CartButtonState.Success -> Icon(Icons.Default.Check, contentDescription = "Added")
            }
        }
    }

    // Observe ViewModel success, update state
    LaunchedEffect(buttonState) {
        if (buttonState == CartButtonState.Loading) {
            delay(2000) // Simulated or driven by ViewModel Flow
            buttonState = CartButtonState.Success
            delay(1500)
            buttonState = CartButtonState.Idle
        }
    }
}

// Infinite loading shimmer effect
@Composable
fun ShimmerBox(modifier: Modifier = Modifier) {
    val infiniteTransition = rememberInfiniteTransition(label = "shimmer")
    val shimmerTranslate by infiniteTransition.animateFloat(
        initialValue = 0f,
        targetValue = 1000f,
        animationSpec = infiniteRepeatable(
            animation = tween(1200, easing = LinearEasing),
            repeatMode = RepeatMode.Restart
        ),
        label = "shimmer_translate"
    )
    Box(
        modifier = modifier.background(
            brush = Brush.horizontalGradient(
                colors = listOf(Color(0x20FFFFFF), Color(0x60FFFFFF), Color(0x20FFFFFF)),
                startX = shimmerTranslate - 200f,
                endX = shimmerTranslate + 200f
            )
        )
    )
}

Key Lines Explained

  • updateTransition(targetState = buttonState, label = "cart_button") — Binds width, color, and content transitions into a single unified state machine.
  • transition.animateDp(transitionSpec = { spring(...) }) — Applies spring physics to the width transition, giving a natural bounce when expanding/collapsing.
  • transition.AnimatedContent { state -> ... } — Nesting AnimatedContent inside updateTransition guarantees child icon/text swap runs in sync with width morphing.
  • rememberInfiniteTransition(label = "shimmer") — Runs a continuous gradient offset loop for placeholder shimmer without creating thread leaks.

5. Alternatives & Trade-offs
API / ApproachProsConsWhen to Pick
animate*AsState Minimal code, declarative, automatic target tracking. Independent animations can drift if state changes rapidly; single property only. Single property animation (alpha, elevation, padding).
updateTransition Atomic multi-property sync, inspector tooling support, nested child transitions. Slightly more boilerplate setup than animate*AsState. Complex components with 2+ coordinated animated properties.
Animatable Full coroutine control, imperative snapTo/animateTo, gesture tracking. Must be orchestrated inside coroutines/effects manually. Touch gestures, physics flings, manual drag-and-drop.
AnimatedVisibility Declarative enter/exit, automated layout add/remove, customizable spec combos. Content remains in composition until exit finishes (can affect layout tree if unkeyed). Conditionally showing or hiding UI elements.
rememberInfiniteTransition Clean declarative looping, lifecycle safe, zero coroutine cancellation boilerplate. Runs indefinitely; requires careful use to prevent GPU drain. Shimmers, loading spinners, background pulses.
Legacy View ObjectAnimator XML reuse in old View hierarchies. Not lifecycle-safe, breaks Compose declarative paradigm, risks memory leaks. Never in pure Jetpack Compose codebases.

Comparison Insights

Architectural Trade-Off

updateTransition vs Multiple animate*AsState: While writing three animate*AsState calls looks simpler, they operate as three independent state listeners. If state switches mid-animation, their individual velocity calculations can desynchronize, causing visual jitter. updateTransition treats the state change as an atomic event across all properties.

6. Pitfalls & Best Practices

1. Omitting the label Parameter

// ❌ BAD — Anonymous animation; impossible to inspect in Android Studio Animation Preview
val alpha by animateFloatAsState(targetValue = if (visible) 1f else 0f)
// ✅ GOOD — Clearly labeled for tooling, layout inspector, and debugging
val alpha by animateFloatAsState(
    targetValue = if (visible) 1f else 0f,
    label = "header_fade_alpha"
)

2. Unnecessary High-Frequency Tree Recomposition

// ❌ BAD — Animating offset directly causes entire outer container to recompose each frame
val offset by animateDpAsState(targetValue = targetOffset, label = "offset")
HeavyCardContainer(modifier = Modifier.offset(y = offset))
// ✅ GOOD — Lambda-based graphicsLayer / offset bypasses recomposition and goes straight to draw/layout phase
val offset by animateDpAsState(targetValue = targetOffset, label = "offset")
HeavyCardContainer(modifier = Modifier.graphicsLayer { translationY = offset.toPx() })

3. Using rememberInfiniteTransition for One-Shot Animations

// ❌ BAD — rememberInfiniteTransition keeps burning frame ticks indefinitely
val anim = rememberInfiniteTransition() // Used to trigger a single bounce
// ✅ GOOD — Use Animatable or LaunchedEffect for one-shot events
val scale = remember { Animatable(1f) }
LaunchedEffect(trigger) {
    scale.animateTo(1.2f, spring())
    scale.animateTo(1.0f, spring())
}

4. AnimatedVisibility Inside LazyColumn Items Without Keys

// ❌ BAD — Reordering or item removal confuses animation state mapping
LazyColumn {
    items(itemList) { item ->
        AnimatedVisibility(visible = item.isVisible) { ... }
    }
}
// ✅ GOOD — Explicit stable key maintains item animation identity
LazyColumn {
    items(items = itemList, key = { it.id }) { item ->
        AnimatedVisibility(visible = item.isVisible) { ... }
    }
}

5. Ignoring System Accessibility Motion Settings

// ❌ BAD — Forces large disorienting animations on motion-sensitive users
val slideOffset by animateDpAsState(targetValue = 500.dp, label = "slide")
// ✅ GOOD — Check reduceMotion and swap physics springs for instant snaps or gentle fades
val spec = if (isReduceMotionEnabled) snap() else spring()

7. Interview Answer Framework

30-Second Answer

"Jetpack Compose uses a declarative, state-driven animation system where animations bridge transitions from a current state to a target state automatically. Instead of mutating Views imperatively, Compose offers two layers: high-level APIs like AnimatedVisibility and AnimatedContent for layout entry/exit choreography, and low-level APIs like animate*AsState and updateTransition for single and multi-property interpolation. All animations are coroutine-safe, interruptible, and parameterized via AnimationSpecs like spring physics or time-based tweens."

2-Minute Structured Answer

"In Jetpack Compose, animation is a first-class citizen of the reactive state model. When state changes, Compose calculates the delta and interpolates values frame by frame, triggering recompositions or draw invalidations.

Architecturally, I think of Compose animation in two tiers. On the high level, we have composables that manage structural layout shifts: AnimatedVisibility handles adding/removing elements with enter/exit specs, and AnimatedContent coordinates transitions between distinct screens or UI modes.

On the lower level, we manipulate raw animated properties. For single values like alpha or elevation, animateFloatAsState or animateDpAsState provides fire-and-forget convenience. When multiple properties must animate in perfect lockstep — such as an Add-to-Cart button changing width, color, and icon together — I use updateTransition to eliminate race conditions and keep transitions synchronized.

For interactive physics and gestures, Animatable provides imperative suspend functions with velocity tracking. Underpinning all of these are AnimationSpec configurations: I default to spring() for touch interactions because physics springs handle mid-animation direction changes without visual hitching, and reserve tween() for fixed duration fades.

Finally, for production performance, I always attach descriptive label parameters for the Android Studio Animation Preview, route high-frequency animations through Modifier.graphicsLayer to skip recomposition phases, and respect accessibility reduceMotion settings."

Must-Mention Points (Show Deep Knowledge)

1
State-Driven Model: Declarative animation transitions from current state to target state rather than imperative property mutation.
2
Two Tiers of APIs: High-level layout transitions (AnimatedVisibility, AnimatedContent) vs low-level value interpolation (animate*AsState, updateTransition, Animatable).
3
updateTransition Synchronization: Use updateTransition for coordinated multi-property state machines to prevent race conditions between independent animations.
4
AnimationSpec Physics vs Time: spring() provides natural velocity-preserving interruptions; tween() is fixed duration with easing curves.
5
Inspection Tooling: Always provide the label parameter to unlock Android Studio Animation Inspector and Layout Inspector debugging.
6
Performance & Accessibility: Defer reads to draw phase via Modifier.graphicsLayer to bypass recomposition, and respect system reduceMotion accessibility preferences.

Likely Follow-up Questions

QuestionShort Answer
How do you prevent animation from causing full recomposition of a Composable? Read the animated state inside a lambda modifier like Modifier.graphicsLayer { alpha = animatedAlpha } or Modifier.offset { IntOffset(x, y) }. This bypasses the Recomposition and Layout phases directly to the Draw phase.
What happens if targetState changes while an animation is in progress? Compose animation APIs are interruptible. They smoothly retarget the trajectory from the current velocity and value without snapping back to initial values.
When should you choose Animatable over animate*AsState? When you need imperative coroutine control (e.g. snapTo() on touch drag, animateTo() with initial velocity on release, or manual sequential chaining).
Why is spring() preferred over tween() for UI interactions? Springs are physics-based and maintain continuous velocity across interrupts, eliminating unnatural abrupt direction changes when users tap rapidly.

9. Interview Questions (Self-Check)
How to use
Try to answer each question before revealing the answer. Click the arrow to reveal.

Basic

B1 — How does Compose animation differ from the traditional View animation system?
Easy▼
Traditional View animations use imperative animators (ObjectAnimator, ValueAnimator) or static XML files that mutate view properties directly, requiring manual lifecycle listener management. Compose animation is declarative and state-driven: UI is a function of state, and animations simply interpolate intermediate values when target state changes. They are coroutine-safe, automatically cancel upon composable disposal, and handle interrupts gracefully.
B2 — What is the purpose of animateFloatAsState and its sister APIs?
Easy▼
animate*AsState functions are low-level fire-and-forget APIs for animating a single value (Float, Dp, Color, Offset, Size, Int). When the provided targetValue changes, Compose automatically starts an animation toward the new target and returns a State<T> that updates continuously throughout the animation.
B3 — What is the difference between AnimatedVisibility and Crossfade?
Easy▼
AnimatedVisibility animates the entry and exit of a single composable (expanding, sliding, fading in/out) as a boolean visibility state changes. Crossfade transitions between two or more distinct pieces of content based on a state key using a smooth opacity fade.

Intermediate

I1 — When would you use updateTransition instead of multiple animate*AsState calls?
Medium▼
Use updateTransition when two or more animated properties (e.g., width, color, elevation, scale) are driven by the same state change and must remain strictly synchronized. Separate animate*AsState calls execute independent animations that can desynchronize or suffer from race conditions when interrupted. updateTransition also enables Android Studio Animation Inspector tooling and allows creating nested child transitions.
I2 — Compare spring() vs tween() AnimationSpec. When should each be chosen?
Medium▼
spring(dampingRatio, stiffness): Physics-based simulation. Has no fixed duration; preserves velocity when interrupted mid-flight, making UI feel natural and responsive. Preferred for touch and user interaction responses.

tween(durationMillis, delay, easing): Time-based animation with a fixed duration and easing curve. Best for pure time-based transitions like opacity crossfades, content reveals, or timed splash transitions.
I3 — Why is it critical to provide the label parameter in Compose animation functions?
Medium▼
The label parameter assigns a human-readable identifier to the animation. This identifier surfaces in Android Studio's Animation Preview and Layout Inspector, allowing developers to inspect curves, pause, scrub, and debug multi-state transitions frame by frame. Without labels, tooling displays generic names that make debugging complex transitions difficult.
I4 — Coding: Implement a pulsing notification badge using rememberInfiniteTransition.
MediumCoding▼
@Composable
fun PulsingBadge(modifier: Modifier = Modifier) {
    val infiniteTransition = rememberInfiniteTransition(label = "badge_pulse_transition")

    val scale by infiniteTransition.animateFloat(
        initialValue = 1.0f,
        targetValue = 1.4f,
        animationSpec = infiniteRepeatable(
            animation = tween(durationMillis = 800, easing = FastOutSlowInEasing),
            repeatMode = RepeatMode.Reverse
        ),
        label = "badge_scale"
    )

    val alpha by infiniteTransition.animateFloat(
        initialValue = 1.0f,
        targetValue = 0.3f,
        animationSpec = infiniteRepeatable(
            animation = tween(durationMillis = 800, easing = FastOutSlowInEasing),
            repeatMode = RepeatMode.Reverse
        ),
        label = "badge_alpha"
    )

    Box(
        modifier = modifier
            .graphicsLayer {
                scaleX = scale
                scaleY = scale
                this.alpha = alpha
            }
            .size(12.dp)
            .background(Color.Red, shape = CircleShape)
    )
}

Senior / Scenario

S1 — Debug Scenario: A list of animated cards experiences severe frame drops and jank during scrolling. How do you diagnose and fix it?
HardScenario▼
Diagnosis:
1. Recomposition Phase Overload: Animated state values (like animated float or Dp) are being read in the composable's body during the Recomposition phase, triggering full subtree recomposition on every single frame tick (60–120 fps).
2. Missing LazyColumn Keys: List items lack stable keys, forcing Compose to recreate animation state as items recycle.

Fixes:
• Defer state reads to the Draw/Layout phase by using lambda modifiers such as Modifier.graphicsLayer { translationY = animatedY } or Modifier.offset { IntOffset(0, animatedY.toInt()) } instead of Modifier.offset(y = animatedY.dp).
• Provide unique, stable keys in items(list, key = { it.id }).
• Use derivedStateOf to clamp animation thresholds and prevent excessive state notifications.
S2 — How would you build a gesture-driven swipe-to-dismiss card that tracks user finger drags in real time and snaps back or flings away on release?
HardScenario▼
Use Animatable(0f) inside a coroutine scope:
1. On Drag: In pointerInput with detectHorizontalDragGestures, call offsetX.snapTo(offsetX.value + dragAmount) to instantly track touch movement without animation lag.
2. On Drag End / Release: Evaluate swipe velocity and distance against a threshold.
3. If threshold is passed, call offsetX.animateTo(targetValue = screenWidth, initialVelocity = flingVelocity) to fling off-screen and trigger item dismissal.
4. If below threshold, call offsetX.animateTo(targetValue = 0f, animationSpec = spring()) to snap back smoothly with physics damping.
S3 — How do you support the Android OS "Reduce Motion" accessibility setting across an entire Compose app design system?
Hard▼
Create a custom CompositionLocal (e.g. LocalReduceMotion) that observes system accessibility settings (via Settings.Global.TRANSITION_ANIMATION_SCALE or window manager settings). In your design system's motion tokens or animation specs, wrap transitions to check LocalReduceMotion.current: 
@Composable
fun <T> adaptiveSpring(): AnimationSpec<T> {
    val reduceMotion = LocalReduceMotion.current
    return if (reduceMotion) snap() else spring()
}
This cleanly replaces complex bouncing scale/slide transitions with instant snaps or subtle opacity crossfades without modifying individual feature composables.
