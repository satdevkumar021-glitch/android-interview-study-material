1. Overview

How Retrofit and OkHttp Compose

Your code Retrofit layer OkHttp layer ───────────────────────────────────────────────────────────────── suspend fun getProduct() → Retrofit processes AnnotationProcessor annotations, builds reads @GET, @Path, etc. HTTP request creates OkHttp Request calls OkHttpClient.newCall() ApplicationInterceptors ↓ Cache check ↓ NetworkInterceptors ↓ TCP connection ↓ Server ↑ (response) ConverterFactory parses response body (Moshi/Gson) maps JSON to data class Returns typed object ◄──────────────────────────────────────────
Senior Mental Model
Retrofit is a type-safe HTTP client — it turns your interface into a working implementation at runtime using dynamic proxies. OkHttp is the actual HTTP engine. Retrofit handles the annotation processing and serialisation; OkHttp handles the connection pool, caching, and interceptors. They're designed to be used together but are independently useful.

2. How It Works

Retrofit API Interface

interface OrderApi {
    // @GET + @Path — GET /orders/{orderId}
    @GET("orders/{orderId}")
    suspend fun getOrder(
        @Path("orderId") orderId: String
    ): OrderDto

    // @GET + @Query — GET /orders?status=PENDING&page=1&pageSize=20
    @GET("orders")
    suspend fun getOrders(
        @Query("status") status: String? = null,
        @Query("page") page: Int = 1,
        @Query("pageSize") pageSize: Int = 20
    ): PagedResponse<OrderDto>

    // @POST + @Body — POST /orders with JSON body
    @POST("orders")
    suspend fun createOrder(
        @Body request: CreateOrderRequest,
        @Header("Idempotency-Key") idempotencyKey: String
    ): OrderDto

    // @PUT — full update
    @PUT("orders/{orderId}")
    suspend fun updateOrder(
        @Path("orderId") orderId: String,
        @Body request: UpdateOrderRequest
    ): OrderDto

    // @DELETE
    @DELETE("orders/{orderId}")
    suspend fun cancelOrder(
        @Path("orderId") orderId: String
    ): Unit  // 204 No Content

    // Response<T> — access the full HTTP response (headers, code, etc.)
    @POST("payments")
    suspend fun processPayment(@Body body: PaymentRequest): Response<PaymentDto>
}

OkHttp Interceptors

// Application Interceptor — runs before cache, for every call
class AuthInterceptor(private val tokenStore: TokenStore) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val token = tokenStore.getAccessToken() ?: return chain.proceed(chain.request())
        val newRequest = chain.request().newBuilder()
            .header("Authorization", "Bearer $token")
            .build()
        return chain.proceed(newRequest)
    }
}

// Logging Interceptor — debug only
val loggingInterceptor = HttpLoggingInterceptor { message ->
    if (BuildConfig.DEBUG) Timber.d(message)
}.apply {
    level = if (BuildConfig.DEBUG) HttpLoggingInterceptor.Level.BODY
            else HttpLoggingInterceptor.Level.NONE
}

3. When to Use

Use suspend fun — Always in new code

Retrofit 2.6+ natively supports Kotlin coroutines with suspend fun. This integrates naturally with coroutine scopes, structured concurrency, and cancellation. Prefer it over Call<T> in all new code.

Use Response<T> when you need HTTP metadata

// Use Response<T> when you need the status code, headers, or error body
@POST("payments")
suspend fun createPayment(@Body body: PaymentRequest): Response<PaymentDto>

// In repository:
val response = api.createPayment(request)
if (response.isSuccessful()) {
    val locationHeader = response.headers()["Location"]  // e.g. /payments/PAY-123
    val dto = response.body()!!
} else {
    val errorJson = response.errorBody()?.string()
}

Converter Factory Selection

For new projects: Moshi with KSP codegen (@JsonClass(generateAdapter = true)) or kotlinx.serialization. Both avoid reflection, support Kotlin null safety, and generate adapters at compile time. Avoid Gson for new code — it doesn't understand Kotlin nullable types correctly.

4. Production Example

E-Commerce App — Full Retrofit + OkHttp Setup

// ── Retrofit interface ───────────────────────────────────────
interface CommerceApi {
    @GET("v1/products")
    suspend fun getProducts(
        @Query("categoryId") categoryId: String?,
        @Query("cursor") cursor: String? = null,
        @Query("limit") limit: Int = 20
    ): CursorPageResponse<ProductDto>

    @POST("v1/cart/items")
    suspend fun addToCart(
        @Body item: AddToCartRequest,
        @Header("Idempotency-Key") key: String
    ): CartItemDto
}

// ── Full OkHttp + Retrofit setup in Hilt module ──────────────
@Module
@InstallIn(SingletonComponent::class)
object NetworkModule {

    @Singleton
    @Provides
    fun provideOkHttpClient(
        tokenStore: TokenStore,
        @ApplicationContext context: Context
    ): OkHttpClient {
        val cache = Cache(File(context.cacheDir, "http"), 10L * 1024 * 1024)
        return OkHttpClient.Builder()
            .cache(cache)
            .connectTimeout(15, TimeUnit.SECONDS)
            .readTimeout(30, TimeUnit.SECONDS)
            .writeTimeout(30, TimeUnit.SECONDS)
            .addInterceptor(AuthInterceptor(tokenStore))          // auth first
            .addInterceptor(buildLoggingInterceptor())             // logging after auth
            .build()
    }

    @Singleton
    @Provides
    fun provideCommerceApi(client: OkHttpClient): CommerceApi =
        Retrofit.Builder()
            .baseUrl("https://api.commerce.com/")
            .client(client)
            .addConverterFactory(MoshiConverterFactory.create(buildMoshi()))
            .build()
            .create(CommerceApi::class.java)

    private fun buildLoggingInterceptor() = HttpLoggingInterceptor().apply {
        level = if (BuildConfig.DEBUG) HttpLoggingInterceptor.Level.BODY
                else HttpLoggingInterceptor.Level.NONE
    }

    private fun buildMoshi() = Moshi.Builder()
        .addLast(KotlinJsonAdapterFactory())
        .build()
}

5. Alternatives & Trade-offs

Retrofit vs Ktor Client vs Manual OkHttp

RetrofitType-safe, annotation-driven, huge ecosystemReflection-based proxy, extra dependencyStandard Android REST APIs
Ktor ClientKMM-compatible, first-class coroutines, flexible DSLLess familiar, more boilerplate for simple APIsKotlin Multiplatform projects
Raw OkHttpFull control, no abstractionsNo type safety, manual serialisationComplex streaming, WebSocket, when Retrofit isn't available

Gson vs Moshi vs kotlinx.serialization

Gson Null Safety Problem
Gson ignores Kotlin's null safety — it will happily set a non-nullable Kotlin field to null if the JSON is missing the field, causing NPE at runtime. Always use Moshi or kotlinx.serialization for Kotlin code.

6. Pitfalls & Best Practices

Common Mistakes

Creating Multiple Retrofit Instances
Retrofit and OkHttpClient are expensive to create and should be singletons. Creating a new instance per request or per screen causes multiple connection pools, multiple thread pools, and wasted memory. Always inject via Hilt as @Singleton.
Logging Authorization Headers in Production
HttpLoggingInterceptor.Level.BODY logs the full Authorization header and request bodies. Guard with if (BuildConfig.DEBUG) — never ship BODY logging to production users. Sensitive data in logs is a security violation.

@Path Encoding

// By default, @Path URL-encodes the value
@GET("users/{userId}/orders")
suspend fun getOrders(@Path("userId") userId: String)
// userId = "user/123" → encodes to "user%2F123" (safe)

// To allow slashes (when path segment contains a full path):
@GET("{fullPath}")
suspend fun getResource(@Path("fullPath", encoded = true) path: String)

ConnectionPool

// OkHttp default: 5 connections, 5 min idle timeout — usually fine
// For high-throughput: increase maxIdleConnections
val connectionPool = ConnectionPool(maxIdleConnections = 10, keepAliveDuration = 5, TimeUnit.MINUTES)
val client = OkHttpClient.Builder()
    .connectionPool(connectionPool)
    .build()

7. Interview Framework

30-Second Answer

"Retrofit is a type-safe HTTP client that sits on top of OkHttp. You define your API as an interface with Retrofit annotations — @GET, @POST, @Path, @Query, @Body, @Header. Retrofit generates a proxy implementation at runtime, reads annotations to build OkHttp requests, passes them to OkHttp, and converts the response using a converter factory like Moshi. OkHttp handles the actual TCP connection, connection pooling, caching, and interceptor chains."

2-Minute Deep Dive

"The interceptor chain is the key OkHttp concept. Application interceptors run for every call including cache hits — used for auth headers and logging. Network interceptors run only for actual network requests — used for low-level headers. Order matters: I always put auth first, then logging, so the log shows the authenticated request. For serialisation: never use Gson in new Kotlin code — it ignores null safety and can set non-nullable fields to null from JSON, causing NPEs. Use Moshi with @JsonClass(generateAdapter = true) for compile-time adapter generation, or kotlinx.serialization. For suspend vs Call: always use suspend in new code — it integrates with structured concurrency, and cancellation happens automatically when the coroutine scope is cancelled."

Must-Mention Points

1
Retrofit wraps OkHttp: Retrofit = annotation processing + converter; OkHttp = HTTP engine + interceptors + pool
2
suspend fun preferred over Call<T> — integrates with structured concurrency
3
Moshi over Gson: Gson doesn't respect Kotlin null safety; Moshi does with codegen
4
Application vs Network Interceptor: Application = every call; Network = only actual HTTP calls
5
Singleton OkHttpClient: one instance per app — connection pool, thread pool, cache are shared
6
Never log in production: Level.BODY is debug-only — logs full headers including auth tokens

Do NOT Go Deeper On

  • Retrofit Rx/Java adapters (replaced by coroutines)
  • Full Moshi/Gson annotation reference
  • OkHttp HTTP/2 multiplexing internals

Follow-up Q&A

QuestionAnswer
"How does Retrofit create the API implementation?"Via Java's dynamic proxy (Proxy.newProxyInstance()). The InvocationHandler intercepts every method call, reads annotations to build an OkHttp Request, executes it, and converts the response.
"What happens if Retrofit has multiple converter factories?"Retrofit tries each factory in order, using the first one that claims it can handle the type. Add the most specific factory first, fallback factory last.
"How do you handle multipart file uploads?"Use @Multipart on the method and @Part on parameters. Wrap files in MultipartBody.Part.createFormData("file", filename, requestBody).

Senior Insight

Senior Signal
The most important production concern is that OkHttp's interceptors run synchronously on OkHttp's thread pool. Never do UI work in an interceptor. Also: if you need to make another network call inside an interceptor (e.g., refresh token), use a synchronous execute() call on the new client, not a coroutine — interceptors aren't coroutine-aware and using suspending functions there requires careful handling to avoid deadlocks.

9. Interview Questions
Basic What is the role of a Retrofit converter factory? ⌄
A converter factory serialises your Kotlin objects into a request body (e.g., data class → JSON string) and deserialises the response body into Kotlin objects (JSON string → data class). Without a converter factory, you'd have to handle raw ResponseBody and call body.string() manually. Factories are added to Retrofit.Builder; Retrofit tries each in order until one claims it can handle the type.
Basic What is the difference between @Path and @Query in Retrofit? ⌄
@Path("id") replaces a placeholder in the URL path: @GET("products/{id}") with @Path("id") productId: String → GET /products/abc123. The value is URL-encoded by default.

@Query("status") appends a query parameter: @GET("products") with @Query("status") status: String → GET /products?status=ACTIVE. Null values are omitted from the URL.
Basic Why should you not use Gson with Kotlin? ⌄
Gson was designed for Java and doesn't understand Kotlin's type system. If a JSON field is missing, Gson sets the corresponding Kotlin property to null — even if it's declared as non-nullable. This bypasses Kotlin's null safety guarantees and causes NullPointerException at runtime when accessing the property. Moshi and kotlinx.serialization are Kotlin-aware and throw a descriptive exception if a required non-nullable field is missing.
Intermediate Explain the difference between Application Interceptors and Network Interceptors. ⌄
Application Interceptors (addInterceptor()): added to the application layer, before OkHttp's core. They run for every call — including responses served from cache (no network request is made). They see the final URL after redirects. Best for: adding auth headers (so cached responses also get the header for consistency), retry logic, and request/response logging at the business level.

Network Interceptors (addNetworkInterceptor()): added to the network layer. They only run when an actual network connection is established. They don't run for cache hits. Best for: modifying response headers, adding Cache-Control headers, low-level traffic analysis or compression.
Intermediate Why should OkHttpClient be a singleton, and what happens if it's not? ⌄
Each OkHttpClient instance maintains its own: thread pool (for async calls), connection pool (open TCP connections), DNS cache, and HTTP response cache. Creating a new client per request means: no connection reuse (expensive TCP handshake every call), no shared cache (disk cache opens/closes repeatedly), wasted threads. A Singleton client reuses connections across requests (HTTP keep-alive), shares the thread pool efficiently, and has a single cache. This significantly reduces latency and memory usage.
Intermediate How do you access the HTTP status code and error body when using Retrofit? ⌄
Change the return type from T to Response<T>: suspend fun getUser(): Response<UserDto>. The Response wrapper provides: response.code() (HTTP status), response.isSuccessful() (200–299), response.body() (parsed body if successful), response.errorBody() (raw error body string for 4xx/5xx), response.headers() (all response headers). Parse the error body with your Moshi instance to get structured error objects.
Intermediate How would you build a Moshi instance with a custom adapter for BigDecimal? ⌄
class BigDecimalAdapter { @FromJson fun fromJson(value: String) = BigDecimal(value); @ToJson fun toJson(value: BigDecimal) = value.toPlainString() }

val moshi = Moshi.Builder().add(BigDecimalAdapter()).addLast(KotlinJsonAdapterFactory()).build()

Add adapters before KotlinJsonAdapterFactory so they take priority. Use addLast() for KotlinJsonAdapterFactory as a general fallback. Register the Moshi instance with Retrofit: .addConverterFactory(MoshiConverterFactory.create(moshi)).
Senior Describe in detail how Retrofit creates the implementation of your API interface. ⌄
When you call retrofit.create(OrderApi::class.java):

1. Retrofit uses Proxy.newProxyInstance(classLoader, arrayOf(OrderApi::class.java), handler) to create a Java dynamic proxy.
2. The InvocationHandler intercepts every method call on the proxy.
3. On getOrder("123"): Retrofit reads annotations (@GET("orders/{orderId}"), @Path("orderId")) from the method's reflection metadata.
4. It builds an OkHttp Request with the resolved URL, headers, and body.
5. For suspend fun: Retrofit uses a SuspendCallAdapterFactory that converts Call<T> to a coroutine-compatible execution using suspendCancellableCoroutine.
6. The request passes through OkHttp's interceptor chain and returns a Response.
7. The configured ConverterFactory deserialises response.body() into the return type.
Senior How would you make a synchronous network call inside an OkHttp interceptor to refresh a token? ⌄
Use a separate, unauthenticated OkHttpClient instance and call .execute() (synchronous, not .enqueue()) on a new Call:

val refreshResponse = unauthClient.newCall(refreshRequest).execute()

Key rules: (1) Use the unauthenticated client — never the same client, or you'll infinite loop. (2) Use execute(), not enqueue() — interceptors run synchronously; enqueue() would require a callback and block the interceptor thread awkwardly. (3) Use a Mutex to ensure only one refresh request happens concurrently when multiple API calls fail with 401 simultaneously. (4) After refreshing, update the token store and retry the original request with chain.proceed(newRequest).
Senior A production app is making too many connections. What OkHttp settings would you investigate? ⌄
1. Multiple OkHttpClient instances: each has its own connection pool. Consolidate to a singleton. Check via profiling — unique pool objects.
2. ConnectionPool configuration: default is 5 idle connections, 5 min keep-alive. For high traffic, increase maxIdleConnections so connections aren't closed and reopened.
3. HTTP/2 not being used: HTTP/2 multiplexes multiple requests over one connection. Verify server supports HTTP/2; OkHttp enables it automatically if the server supports ALPN.
4. Aggressive timeouts: very short timeouts cause premature connection closure. Check if keepAliveDuration aligns with server's connection timeout.
5. retryOnConnectionFailure: if true, OkHttp opens new connections on failure — can compound connection issues during server outages.
