2. Build Pipeline

Source → Play Store

Kotlin/Java Sources │ ▼ Kotlin Compiler (kotlinc) Kotlin → .class files (JVM bytecode) │ ▼ D8 / R8 (release builds use R8, debug uses D8) .class → .dex (Dalvik Executable) R8 also: shrinks + obfuscates + optimizes │ ▼ aapt2 (Android Asset Packaging Tool v2) res/ → compiled resources + R.java │ ▼ APK Packager .dex + compiled resources + manifest → .apk or .aab │ ▼ zipalign (aligns 4-byte boundaries for memory-mapped access) │ ▼ apksigner (signs with keystore — v1/v2/v3 signature schemes) │ ▼ Final: signed .apk or .aab → Play Console

D8 vs R8

ToolUsed inDoes
D8Debug buildsConverts .class → .dex only; no shrinking
R8Release buildsConverts + shrinks + obfuscates + optimizes (replaces ProGuard)

3. APK vs AAB & Signing

APK vs Android App Bundle (AAB)

AspectAPKAAB
File extension.apk.aab
Install directlyYes — sideload or ADBNo — Play Store only
Device-specific splitNo — one APK for all devicesYes — Play generates device-optimized APK
Download sizeLarger (all resources included)Smaller (~15–20% reduction typical)
Play Store requirementAccepted but AAB preferredRequired for new apps since Aug 2021
Native librariesAll ABIs includedOnly ABI for device
How AAB Works
You upload one .aab to Play. When a user installs, Play generates a device-specific APK containing only: the ABI for that CPU, the screen density resources for that screen, and the language resources for installed languages. Result: much smaller download and install.

Keystore & Signing

# Generate keystore (do this ONCE, store securely — never commit to git!)
keytool -genkey -v -keystore my-release-key.jks \
  -alias my-key-alias -keyalg RSA -keysize 2048 \
  -validity 10000

# If you lose the keystore, you CANNOT update your app on Play Store
# Google Play App Signing can back it up — enroll early
// app/build.gradle — signing config
android {
    signingConfigs {
        release {
            storeFile = file(System.getenv("KEYSTORE_PATH"))  // from CI env var
            storePassword = System.getenv("KEYSTORE_PASS")
            keyAlias = System.getenv("KEY_ALIAS")
            keyPassword = System.getenv("KEY_PASS")
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.release
        }
    }
}
Critical: Never Commit Keystore
Never commit your .jks keystore file or passwords to git. Store the keystore in a secure vault (AWS Secrets Manager, GitHub Secrets) and inject via CI environment variables. Add *.jks and *.keystore to .gitignore.

4. R8 & ProGuard

What R8 Does

  • Shrinking: removes unused classes, methods, and fields from your code and libraries
  • Obfuscation: renames classes/methods to short names (a, b, c) — makes reverse engineering harder and reduces DEX size
  • Optimization: inlines short methods, removes dead code, propagates constants
// Enable in build.gradle (release builds)
buildTypes {
    release {
        minifyEnabled = true      // enables R8
        shrinkResources = true    // removes unused resources too
        proguardFiles(
            getDefaultProguardFile("proguard-android-optimize.txt"),
            "proguard-rules.pro"     // your custom rules
        )
    }
}

Keep Rules

# proguard-rules.pro

# Keep data classes used with Gson/Moshi/Retrofit (reflection-based parsing)
-keep class com.myapp.data.model.** { *; }

# Keep classes annotated with @Keep
-keep @androidx.annotation.Keep class * { *; }

# Keep Retrofit interfaces
-keep interface com.myapp.network.** { *; }

# Keep enum values (used in JSON deserialization)
-keepclassmembers enum * { public static **[] values(); public static ** valueOf(java.lang.String); }

# Suppress notes for third-party libraries
-dontnote okhttp3.**
-dontwarn okhttp3.**
Most Common R8 Crash Pattern
You add a new data class for a JSON API response. It works in debug. In release, the class is renamed or fields are removed by R8. Retrofit/Gson can't parse the JSON → null fields or ClassNotFoundException. Fix: add -keep rule or annotate with @Keep, or use code generation (kotlinx.serialization with kotlin-reflect kept).

Debugging Obfuscated Crashes

# Use retrace to de-obfuscate a crash stack trace
# mapping.txt is generated at: app/build/outputs/mapping/release/mapping.txt
retrace app/build/outputs/mapping/release/mapping.txt obfuscated-stacktrace.txt

# Crashlytics automatically de-obfuscates using mapping.txt uploaded by the
# firebase-crashlytics Gradle plugin at build time

5. Play Console & Rollout

Release Tracks

TrackWho sees itUse case
Internal TestingUp to 100 testers (by Google account)Automated CI builds, daily smoke test
Closed Testing (Alpha)Selected testers (email list or group)QA team, beta testers
Open Testing (Beta)Anyone who opts inPre-release feedback, wider testing
ProductionAll users (staged rollout possible)Official release

Staged Rollout

  • Start at 10% of users → monitor crash-free rate for 24–48 hours
  • Increase to 50% if metrics are green
  • Increase to 100% if no regressions
  • Emergency halt: Play Console → Release → Halt rollout — stops further distribution of the new version
  • Users who already updated keep the new version (you cannot force downgrade)

Version Code Strategy

// app/build.gradle — CI-driven version code
android {
    defaultConfig {
        // CI sets GITHUB_RUN_NUMBER or BITRISE_BUILD_NUMBER env var
        versionCode = (System.getenv("BUILD_NUMBER")?.toIntOrNull()) ?: 1
        versionName = "2.14.0"  // semantic version for humans
    }
}

// Rules:
// 1. versionCode must ALWAYS increase with every Play Store upload
// 2. Never reuse a versionCode — Play will reject the upload
// 3. versionName is shown to users; versionCode is used by Play for ordering

7. Interview Framework
How to Answer Build Pipeline Questions
Walk the pipeline from source to Play Store: source → Kotlin compile → D8/R8 → resources (aapt2) → APK/AAB → zipalign → apksign → Play Console. Pause to explain R8 (shrink, obfuscate, optimize) and why keep rules matter. End with staged rollout.

Common Questions & Answers

  • "APK vs AAB — which do you ship and why?" → AAB required for new apps. Play generates device-specific APK. Smaller download, same functionality.
  • "What is R8?" → Replacement for ProGuard. Combines shrinking (remove unused code), obfuscation (rename), and optimization (inline methods). Enabled with minifyEnabled=true.
  • "How do you debug a crash in a release build?" → Get the obfuscated stack trace from Crashlytics (auto-symbolicated if mapping.txt was uploaded). If not, use retrace with mapping.txt manually.
  • "How do you manage the keystore securely?" → Store in secret manager (not git). Inject path and passwords as CI environment variables. Enroll in Google Play App Signing as backup.

9. Interview Questions
Walk me through the Android build pipeline from source code to Play Store.
Medium▼
Kotlin source → Kotlin compiler (.class files) → R8 (shrink/obfuscate/optimize → .dex) + aapt2 (compile resources) → APK packager (.dex + compiled resources + AndroidManifest → .apk or .aab) → zipalign (4-byte alignment) → apksigner (sign with keystore) → upload to Play Console.
What does R8 do and why is it important?
Easy▼
R8 is the replacement for ProGuard that runs as part of the release build. It does three things: (1) Shrinking — removes unused classes, methods, and fields from your code and all libraries; (2) Obfuscation — renames classes/methods to short names (a, b, c) reducing DEX size and making reverse engineering harder; (3) Optimization — inlines short methods, removes dead code. Enabled with minifyEnabled=true.
Why does my app crash in release but not debug? How do you debug it?
Hard▼
Most likely R8 removed or renamed a class/field used via reflection (JSON parsing, serialization, dependency injection). Debug steps: (1) Check Crashlytics — Crashlytics auto-symbolicated the trace if mapping.txt was uploaded; (2) Use retrace manually with mapping.txt; (3) Look for ClassNotFoundException or NullPointerException where a field is null despite being set in JSON; (4) Add -keep rules for the affected class and test the release build.
What is the difference between APK and AAB? Which should you ship?
Easy▼
APK is a complete installable file — contains code, resources for all screen densities, all CPU ABIs, all languages. AAB (Android App Bundle) is an upload format — Play Store generates a device-specific APK from it containing only what that device needs. AAB results in 15–20% smaller downloads. AAB is required for new apps on Play Store since Aug 2021. Ship AAB.
How do you manage keystore security in a team?
Medium▼
Never commit the .jks keystore to git. Store it in a secrets manager (AWS Secrets Manager, GitHub Encrypted Secrets, HashiCorp Vault). In CI, inject keystore path and passwords as environment variables into the build. Add *.jks and *.keystore to .gitignore. Enroll in Google Play App Signing so Google holds a backup — if you lose your keystore, you can still publish updates.
What are -keep rules and when do you need them?
Medium▼
Keep rules prevent R8 from removing or renaming classes/members that are referenced via reflection at runtime. You need them for: data classes used with Gson/Moshi/Retrofit JSON parsing, enums used in JSON, Parcelable implementations, classes loaded by Class.forName(), custom View constructors used in XML. Use @Keep annotation or -keep rules in proguard-rules.pro.
What is a staged rollout and how does it protect production?
Easy▼
A staged rollout releases the new version to a percentage of users first. Start at 10%, monitor crash-free rate and ANR rate for 24–48 hours. If metrics are healthy, expand to 50%, then 100%. If crash-free rate drops (e.g., from 99.5% to 97%), immediately halt the rollout in Play Console — new users stop receiving the update. Existing users who updated keep the new version; you cannot force a downgrade.
How do you set versionCode in CI and what is the rule?
Easy▼
Set versionCode to the CI build number: System.getenv("BUILD_NUMBER")?.toIntOrNull() ?: 1. This ensures every build has a unique, monotonically increasing versionCode. The rule: versionCode must always increase with every Play Store upload. Play rejects uploads with a versionCode ≤ current published versionCode. Never manually set it — always use CI automation.
What is zipalign and why is it needed?
Easy▼
zipalign aligns all uncompressed data in an APK on 4-byte boundaries. This allows the OS to memory-map the APK file directly, improving performance and reducing RAM usage at runtime. It must be applied BEFORE signing (apksigner) — aligning after signing invalidates the signature. Android Studio and Gradle handle this automatically in release builds.
What are the Play Console release tracks and when do you use each?
Medium▼
Internal Testing: up to 100 specific testers, instant publish (no review). Use for automated CI builds and smoke tests. Closed (Alpha): selected testers via email or group. Use for QA and beta testers. Open (Beta): any user can opt in. Use for wide pre-release feedback. Production: all users; staged rollout available. Promotions flow internal → alpha → beta → production. Each track requires the build to pass Google's review for production.
