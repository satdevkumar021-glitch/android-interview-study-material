6B — Flow Operators

Transforming, combining, flatMapping, timing, error handling, and lifecycle operators. Production examples for each. flatMapConcat vs flatMapMerge vs flatMapLatest comparison.

ID: 6B ⭐ Tier 1
🔍
1. Overview

Operator categories

  • Transforming: map, filter, transform — change the data in the stream
  • Combining: combine, zip, merge — merge multiple flows into one
  • FlatMapping: flatMapConcat, flatMapMerge, flatMapLatest — map each value to a new Flow
  • Timing: debounce, sample, throttle, distinctUntilChanged — control emission rate
  • Error handling: catch, retry, retryWhen — handle upstream errors
  • Lifecycle: onStart, onCompletion, onEach — side effects in the chain
Mental Model
Flow operators are lazy — they don't execute until collect() is called. Each operator creates a new Flow that wraps the upstream. Think of the chain as a pipeline declaration, not execution. The entire chain runs when collected.

2. Transform & Filter
// map: transform each value
repo.getPrices()                  // Flow<RawPrice>
    .map { raw -> formatPrice(raw) } // Flow<String>
    .collect { displayPrice(it) }

// filter: drop values that don't match predicate
transactionFlow
    .filter { it.amount > BigDecimal.ZERO }  // only positive
    .collect { showTransaction(it) }

// transform: most flexible — can emit multiple values or skip
userFlow
    .transform { user ->
        if (user.isVerified) {
            emit(user)                  // emit the user
            emit(user.copy(cached = true)) // emit modified copy
        }
        // if not verified: emit nothing (skip)
    }
    .collect { handleUser(it) }

// mapNotNull: map + filter null results
eventFlow
    .mapNotNull { event -> event as? PaymentEvent }
    .collect { handlePayment(it) }

3. Combining Flows

combine — emit when any source changes

// combine: re-emits when EITHER source emits (uses latest from other)
val searchFlow: Flow<String> = searchInput.asFlow()
val filterFlow: Flow<FilterOptions> = activeFilters

searchFlow.combine(filterFlow) { query, filters ->
    repo.search(query, filters)
}.collect { results -> showResults(results) }
// If user types OR changes filter → new search triggered

zip — pair values one-to-one

// zip: pairs emissions 1:1, waits for BOTH to emit
val namesFlow = flowOf("Alice", "Bob", "Carol")
val scoresFlow = flowOf(95, 87, 92)

namesFlow.zip(scoresFlow) { name, score ->
    "$name: $score"
}.collect { println(it) }
// Outputs: "Alice: 95", "Bob: 87", "Carol: 92"
// Zip ends when shorter flow completes

merge — interleave emissions

// merge: combines multiple flows, emits as they arrive
val uiUpdates = merge(
    networkStatusFlow,   // emits when connectivity changes
    batteryLevelFlow,    // emits when battery changes
    userActionFlow       // emits on user interaction
)
uiUpdates.collect { update -> handleUpdate(update) }

4. FlatMap Operators

FlatMap operators transform each emission into a new Flow, then flatten the results. The key difference is how concurrent inner flows are handled.

flatMapConcat — sequential, in-order

// flatMapConcat: waits for each inner flow to complete before starting next
// Preserves order, sequential — like a queue
orderIds.flatMapConcat { id ->
    repo.getOrderDetails(id)  // returns Flow<OrderDetail>
}.collect { detail -> showDetail(detail) }
// Order 1 fully loaded before Order 2 starts

flatMapMerge — concurrent

// flatMapMerge: starts all inner flows concurrently, interleaves results
// Faster, but order is NOT guaranteed
productIds.flatMapMerge { id ->
    priceApi.getPriceStream(id)  // live price updates per product
}.collect { price -> updatePriceDisplay(price) }
// All price streams run in parallel — fastest delivery

flatMapLatest — cancel previous on new emission

// flatMapLatest: cancels the PREVIOUS inner flow when a new source emits
// Only the latest inner flow survives
searchQuery
    .debounce(300)
    .flatMapLatest { query ->
        repo.search(query)  // if user types again, this is cancelled
    }
    .collect { results -> showResults(results) }
// ✅ Perfect for search — only the latest query matters

5. Timing & Error Handling

Timing operators

// debounce: emit only after X ms of silence
searchInput.debounce(300).collect { query -> search(query) }
// User types "kotlin" — only "kotlin" sent after 300ms pause

// distinctUntilChanged: skip if value same as previous
userFlow.distinctUntilChanged().collect { render(it) }
// Only re-renders when actual user data changes

// sample: emit most recent value every X ms interval
sensorFlow.sample(1000).collect { reading -> updateUI(reading) }
// Sensor fires 60fps — sample(1000) → 1 update/second to UI

Error handling operators

// catch: handle upstream exceptions, emit fallback
repo.getBalance()
    .catch { e ->
        emit(Balance.Unavailable)  // emit fallback value
        logError(e)
    }
    .collect { showBalance(it) }

// retry: re-subscribe on error
networkFlow
    .retry(3) { e -> e is IOException }  // retry up to 3 times for IO errors
    .collect { handleData(it) }

// retryWhen: retry with exponential backoff
apiFlow
    .retryWhen { cause, attempt ->
        if (cause is IOException && attempt < 3) {
            delay(1000L * (2.pow(attempt.toInt()))) // 1s, 2s, 4s
            true   // retry
        } else false   // don't retry
    }
    .collect { handleData(it) }

6. Lifecycle Operators

onStart, onEach, onCompletion

// onStart: called before flow starts collecting
repo.getProducts()
    .onStart { _loading.value = true }
    .onEach { product -> cacheProduct(product) }  // side effect per item
    .onCompletion { cause ->
        _loading.value = false
        if (cause != null) logError(cause)
    }
    .collect { displayProduct(it) }

// Production: full pipeline with loading, error, completion
fun getTransactionFlow(accountId: String) =
    repo.transactions(accountId)
        .onStart { emit(Resource.Loading) }
        .map { Resource.Success(it) }
        .catch { emit(Resource.Error(it)) }
        .onCompletion { /* cleanup */ }

7. Interview Framework

30-second answer

"Flow operators are lazy — they build a pipeline that executes on collect. Key operators: map/filter for transformation, combine/zip/merge for combining flows, flatMapLatest for search (cancel previous on new query), debounce for typing delays, catch/retry for error handling, and onStart/onCompletion for loading states."

2-minute answer

"The most important distinction is the three flatMap operators. flatMapConcat is sequential — each inner flow must complete before the next starts, preserving order. flatMapMerge is concurrent — all inner flows run simultaneously, results interleave. flatMapLatest cancels the previous inner flow when a new source emission arrives — essential for search where only the latest query matters.

For combining flows: combine fires when either source emits using the latest from the other — perfect for search + filter combinations. zip pairs emissions 1:1, waiting for both — good for correlated datasets. merge interleaves from multiple sources — good for event aggregation.

For error handling: catch handles exceptions and can emit fallback values. retryWhen gives you control over retry timing — exponential backoff for network resilience. debounce with 300ms is the standard search debounce pattern in Android."

Must-mention points

1
flatMapLatest for search — cancels previous; flatMapConcat for ordered; flatMapMerge for parallel
2
combine vs zip — combine = either emits with latest; zip = 1:1 pairing
3
debounce(300) — standard search debounce
4
catch — handles upstream errors, can emit fallback; does NOT catch downstream errors
5
Operators are lazy — pipeline executes only on collect

Follow-up Q&A

Q: "What's the difference between debounce and sample?"

A: debounce(n) waits until the source has been silent for n ms before emitting — useful for typing (only emit after user stops). sample(n) emits the most recent value every n ms on a fixed schedule — useful for sensor data where you want regular UI updates regardless of how fast the sensor fires.

Q: "Does catch handle errors thrown by the collector?"

A: No. catch only handles exceptions from the upstream (the flow chain above it). Exceptions thrown inside the collect { } lambda are NOT caught by catch. Use a try/catch inside the collect lambda for downstream errors.

Senior insight

Senior Insight
In a banking app, combine the search query flow with the account filter flow and the sort preference flow using combine: combine(searchFlow, filterFlow, sortFlow) { q, f, s → Query(q,f,s) }.flatMapLatest { query → repo.search(query) }.catch { emit(Error(it)) }. This creates a reactive search that automatically re-fetches whenever any input changes, with only the latest result kept.

9. Interview Questions
What is the difference between map and transform in Flow?
Basic⌄
map transforms each emission 1:1 — one input always produces exactly one output. transform is more flexible — you can call emit() zero or multiple times. Use transform to skip some emissions (like filter) or to expand one value into multiple (like a 1:n mapping).
What does debounce do and when would you use it?
Basic⌄
debounce(n) only emits a value after n milliseconds of silence from the upstream. If a new value arrives before n ms, the timer resets. Classic use case: search-as-you-type — don't fire an API call for every keystroke; wait until the user pauses typing for 300ms.
Explain the difference between combine and zip.
Basic⌄
combine: emits a new combined value whenever either source emits, using the latest value from the other. If flow A emits 3 times and flow B emits 2 times, you can get up to 5 combined emissions. zip: pairs emissions 1:1. Waits for both sources to emit before combining. If A emits 3 times and B emits 2 times, you get 2 paired emissions (stops when the shorter one completes).
What is the difference between flatMapConcat, flatMapMerge, and flatMapLatest?
Intermediate⌄
flatMapConcat: sequential — waits for each inner flow to complete before starting the next. Order guaranteed. Use for ordered operations like paginated loading. flatMapMerge: concurrent — starts all inner flows simultaneously. Results arrive in any order. Use for parallel fetches. flatMapLatest: when a new outer emission arrives, the previous inner flow is cancelled and a new one starts. Only the latest matters. Use for search queries.
Does the catch operator handle exceptions thrown inside the collect lambda?
Intermediate⌄
No. catch is a transparent operator that only catches exceptions thrown by the upstream (the flow chain above it in the pipeline). Exceptions thrown inside the collect { } collector lambda are downstream and are NOT intercepted by catch. To handle collector exceptions, wrap the collect call in a try/catch.
How would you implement exponential backoff retry in a Flow?
Intermediate⌄
Use retryWhen: .retryWhen { cause, attempt -> if (cause is IOException && attempt < 3) { delay(1000L * (1 shl attempt.toInt())); true } else false }. The attempt starts at 0. Delays: 1000ms, 2000ms, 4000ms (powers of 2). Only retry IOExceptions, not business logic errors. After 3 attempts, return false to stop retrying and let the exception propagate.
Build a search pipeline that: debounces 300ms, ignores blank input, cancels stale requests, and handles network errors gracefully.
Intermediate⌄
searchQuery.debounce(300).filter { it.isNotBlank() }.distinctUntilChanged().flatMapLatest { query -> repo.search(query).catch { emit(SearchResult.Error(it)) } }.collect { result -> renderResult(result) }. Explanation: debounce waits for typing pause; filter ignores empty; distinctUntilChanged avoids re-searching same query; flatMapLatest cancels previous request on new keystroke; catch inside the flatMapLatest handles errors per query without breaking the outer flow.
What is onEach and how does it differ from map?
Senior⌄
onEach is for side effects — it performs an action on each emission but passes the original value through unchanged. map transforms the value into a different value. Use onEach for logging, caching, analytics tracking, or setting loading states without changing the stream's data type. Example: flow.onEach { cache.save(it) }.map { toUiModel(it) } — cache the raw data, then transform to UI model.
How would you merge live price updates for 100 products into a single UI-updating stream without overwhelming the main thread?
Senior⌄
Use flatMapMerge(concurrency = 20) to limit concurrent inner flows: productIds.flatMapMerge(concurrency = 20) { id -> priceSocket.streamPrice(id) }.conflate(). The concurrency parameter prevents 100 simultaneous socket connections. conflate() at the end drops intermediate updates if the UI can't keep up — only the latest price per product matters. Then collect on Main dispatcher for UI updates. The concurrency limit matches realistic socket pool size.
Explain how you would use the Resource pattern (Loading/Success/Error) with Flow operators.
Senior⌄
Wrap the repository flow: fun getDataFlow(id: String): Flow<Resource<Data>> = repo.getStream(id).map<Data, Resource<Data>> { Resource.Success(it) }.onStart { emit(Resource.Loading) }.catch { emit(Resource.Error(it)) }. The onStart emits Loading before any data arrives. map wraps success data. catch catches upstream errors and emits Error. The UI collects a single flow that handles all three states. Important: onStart must come before catch so the Loading emission isn't caught by catch.
