In Kotlin, use ArrayDeque for both Stack and Queue — it's the recommended double-ended queue. Stack: addLast/removeLast (LIFO). Queue: addLast/removeFirst (FIFO). Never use java.util.Stack or LinkedList in Kotlin interviews.

2. Stack — Balanced Parentheses

Stack Implementation

// Using ArrayDeque as Stack (LIFO)
class Stack<T> {
    private val deque = ArrayDeque<T>()
    fun push(item: T) = deque.addLast(item)
    fun pop(): T = deque.removeLast()
    fun peek(): T = deque.last()
    fun isEmpty() = deque.isEmpty()
    val size get() = deque.size
}

// Or use ArrayDeque directly (more idiomatic):
val stack = ArrayDeque<Char>()
stack.addLast('a')    // push
stack.removeLast()   // pop
stack.last()        // peek

Use Case: Balanced Parentheses Checker

// "({[]})" → true,  "({[})" → false,  "(((" → false
fun isBalanced(s: String): Boolean {
    val stack = ArrayDeque<Char>()
    val pairs = mapOf(')' to '(', ']' to '[', '}' to '{')

    for (ch in s) {
        when (ch) {
            '(', '[', '{' -> stack.addLast(ch)   // open bracket: push
            ')', ']', '}' -> {
                // close bracket: pop and check if it matches
                if (stack.isEmpty() || stack.removeLast() != pairs[ch]) return false
            }
        }
    }
    return stack.isEmpty()   // stack must be empty if fully balanced
}

println(isBalanced("({[]})"))  // true
println(isBalanced("({[})"))   // false — } doesn't match [
println(isBalanced("((("))     // false — stack not empty
println(isBalanced(""))        // true — empty string is balanced

queue.removeFirst() // dequeue (remove from front)
queue.first()       // peek front

Use Case: BFS (Breadth-First Search) on a Graph

// BFS visits all nodes at distance 1, then distance 2, etc.
fun bfs(graph: Map<Int, List<Int>>, start: Int): List<Int> {
    val visited = HashSet<Int>()
    val queue = ArrayDeque<Int>()
    val result = mutableListOf<Int>()

    queue.addLast(start)
    visited.add(start)

    while (queue.isNotEmpty()) {
        val node = queue.removeFirst()
        result.add(node)

        graph[node]?.forEach { neighbor ->
            if (neighbor !in visited) {
                visited.add(neighbor)
                queue.addLast(neighbor)
            }
        }
    }
    return result
}

val graph = mapOf(
    1 to listOf(2, 3),
    2 to listOf(4),
    3 to listOf(5),
    4 to emptyList(),
    5 to emptyList()
)
println(bfs(graph, 1))  // [1, 2, 3, 4, 5]

4. LinkedList — Implementation
// Singly LinkedList Node
data class Node<T>(val value: T, var next: Node<T>? = null)

class LinkedList<T> {
    private var head: Node<T>? = null

    // Append to end — O(n)
    fun append(value: T) {
        val newNode = Node(value)
        if (head == null) { head = newNode; return }
        var current = head
        while (current?.next != null) current = current.next
        current?.next = newNode
    }

    // Prepend to front — O(1)
    fun prepend(value: T) {
        head = Node(value, head)
    }

    // Delete first occurrence of value — O(n)
    fun delete(value: T) {
        if (head?.value == value) { head = head?.next; return }
        var current = head
        while (current?.next != null) {
            if (current.next?.value == value) {
                current.next = current.next?.next
                return
            }
            current = current.next
        }
    }

    // Print all values
    fun toList(): List<T> {
        val result = mutableListOf<T>()
        var current = head
        while (current != null) {
            result.add(current.value)
            current = current.next
        }
        return result
    }
}

val list = LinkedList<Int>()
list.append(1); list.append(2); list.append(3)
println(list.toList())  // [1, 2, 3]
list.delete(2)
println(list.toList())  // [1, 3]

5. Floyd's Cycle Detection (Tortoise & Hare)

Detect a cycle in a linked list in O(n) time, O(1) space — no HashSet needed.

// Mutable node for cycle creation:
class MutableNode(val value: Int, var next: MutableNode? = null)

fun hasCycle(head: MutableNode?): Boolean {
    var slow = head    // moves 1 step at a time (tortoise)
    var fast = head    // moves 2 steps at a time (hare)

    while (fast != null && fast.next != null) {
        slow = slow?.next
        fast = fast.next?.next
        if (slow == fast) return true   // they met → cycle exists
    }
    return false   // fast reached null → no cycle
}

// Create: 1 → 2 → 3 → 4 → 2 (cycle back to node 2)
val n1 = MutableNode(1); val n2 = MutableNode(2)
val n3 = MutableNode(3); val n4 = MutableNode(4)
n1.next = n2; n2.next = n3; n3.next = n4; n4.next = n2   // cycle!
println(hasCycle(n1))   // true

val linear = MutableNode(1); linear.next = MutableNode(2)
println(hasCycle(linear)) // false
Why Floyd's Works
If there's a cycle, the fast pointer enters it and laps the slow pointer. Since fast moves 2 steps and slow moves 1, fast gains 1 step per iteration on slow. Eventually fast == slow (fast lapped slow). If there's no cycle, fast reaches null. O(n) time, O(1) space — no HashSet of visited nodes needed.

6. Binary Search
// Classic binary search: find target in sorted array
// Returns index or -1 if not found

// Iterative — O(log n) time, O(1) space (preferred)
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0; var hi = nums.size - 1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2   // avoids integer overflow vs (lo+hi)/2
        when {
            nums[mid] == target -> return mid
            nums[mid] < target  -> lo = mid + 1
            else               -> hi = mid - 1
        }
    }
    return -1
}

println(binarySearch(intArrayOf(1,3,5,7,9), 5))   // 2 (index)
println(binarySearch(intArrayOf(1,3,5,7,9), 6))   // -1 (not found)

// Recursive — O(log n) time, O(log n) stack space
fun binarySearchRec(nums: IntArray, target: Int, lo: Int = 0, hi: Int = nums.size-1): Int {
    if (lo > hi) return -1
    val mid = lo + (hi - lo) / 2
    return when {
        nums[mid] == target -> mid
        nums[mid] < target  -> binarySearchRec(nums, target, mid + 1, hi)
        else               -> binarySearchRec(nums, target, lo, mid - 1)
    }
}

Find First / Last Occurrence

// Find FIRST occurrence of target (handles duplicates)
fun findFirst(nums: IntArray, target: Int): Int {
    var lo = 0; var hi = nums.size - 1; var result = -1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2
        when {
            nums[mid] == target -> { result = mid; hi = mid - 1 }  // keep searching left
            nums[mid] < target  -> lo = mid + 1
            else               -> hi = mid - 1
        }
    }
    return result
}

7. Interview Framework
Data Structure Selection
Interviewer: "Design X." You: think about what operations are needed, then pick the right structure. Stack → LIFO. Queue → FIFO, BFS. HashMap → O(1) lookup. LinkedList → O(1) insert at known position. Heap → find min/max efficiently.

Binary Search Template (Memorize)

// Template for any binary search problem:
var lo = 0; var hi = n - 1
while (lo <= hi) {
    val mid = lo + (hi - lo) / 2   // NEVER (lo + hi) / 2 — can overflow
    if (condition(mid)) {
        result = mid; hi = mid - 1  // or lo = mid + 1 for last occurrence
    } else if (tooSmall(mid)) {
        lo = mid + 1
    } else {
        hi = mid - 1
    }
}

9. Practice Questions
Why is mid = lo + (hi - lo) / 2 preferred over mid = (lo + hi) / 2?
Medium▼
(lo + hi) can overflow when lo and hi are both large (e.g., lo = Int.MAX_VALUE / 2, hi = Int.MAX_VALUE / 2 + 1 — their sum exceeds Int.MAX_VALUE). lo + (hi - lo) / 2 is mathematically equivalent but safe because (hi - lo) is always smaller than hi, and adding it to lo can't overflow if the original values fit in Int. This is a well-known interview trick to show awareness of integer overflow.
Explain how Floyd's cycle detection works with a concrete example.
Medium▼
List: 1→2→3→4→2 (cycle at 2). Slow moves 1 step, fast moves 2: Start: slow=1, fast=1. Step1: slow=2, fast=3. Step2: slow=3, fast=2. Step3: slow=4, fast=4. slow==fast → cycle detected. Intuition: if there's a cycle, fast enters it and gains 1 step per round on slow. Eventually they occupy the same node. If no cycle, fast reaches null. O(1) space — no extra memory for visited set.
When would you use a Stack vs a Queue? Give Android examples.
Easy▼
Stack (LIFO): back navigation history (Activity back stack), undo/redo operations, DFS traversal, balanced parentheses, call stack simulation. Queue (FIFO): BFS traversal, task processing in order (WorkManager queue), network request queuing, event ordering. Android's Fragment back stack is literally a Stack. BFS for finding shortest path in a graph (e.g., social network distance) uses a Queue.
Write the algorithm to reverse a linked list.
Medium▼
fun reverseList(head: Node?): Node? { var prev: Node? = null; var current = head; while (current != null) { val next = current.next; current.next = prev; prev = current; current = next }; return prev }. Three-pointer technique: save next, point current back to prev, advance both. After loop, prev is the new head. O(n) time, O(1) space. Iterative is preferred over recursive for lists (avoids stack overflow on long lists).
How does binary search achieve O(log n) — what is being halved each iteration?
Easy▼
Each iteration halves the search space. Starting with n elements: after 1 step → n/2, after 2 → n/4, after k → n/2^k. When n/2^k = 1, we've found it or exhausted the search. Solving n/2^k = 1 → k = log₂(n). So binary search takes at most log₂(n) iterations. For n=1,000,000: only 20 steps. This requires the array to be sorted — binary search cannot be applied to unsorted data.
How would you implement a stack that supports getMin() in O(1)?
Hard▼
Use two stacks: main stack and min stack. On push(x): push x to main; push min(x, minStack.lastOrNull() ?: x) to minStack. On pop(): pop from both. getMin() = minStack.last(). The min stack always has the current minimum at its top — it tracks the minimum at each state of the main stack. Space: O(n). All operations O(1). class MinStack { private val stack = ArrayDeque<Int>(); private val minStack = ArrayDeque<Int>(); fun push(x: Int) { stack.addLast(x); minStack.addLast(minOf(x, minStack.lastOrNull() ?: x)) }; fun pop() { stack.removeLast(); minStack.removeLast() }; fun getMin() = minStack.last() }
Write binary search to find the first element ≥ target (lower bound).
Hard▼
fun lowerBound(nums: IntArray, target: Int): Int { var lo = 0; var hi = nums.size; while (lo < hi) { val mid = lo + (hi - lo) / 2; if (nums[mid] < target) lo = mid + 1 else hi = mid }; return lo }. Returns the index of the first element ≥ target (or nums.size if all elements are smaller). This is the classic lower_bound from C++ STL. Note: loop condition is lo < hi (not ≤) and hi starts at nums.size to handle the "all smaller" case.
What is the time complexity of finding the middle of a linked list, and how?
Easy▼
O(n) time, O(1) space using the slow/fast pointer technique (same as Floyd's). slow moves 1 step, fast moves 2. When fast reaches the end, slow is at the middle. fun findMiddle(head: Node?): Node? { var slow = head; var fast = head; while (fast?.next != null) { slow = slow?.next; fast = fast.next?.next }; return slow }. For even-length list, returns the second-middle node. This is also used in merge sort for linked lists.
Implement a valid parentheses checker that also returns the positions of unmatched brackets.
Hard▼
Instead of just a Char stack, push (char, index) pairs. When a close bracket is encountered and matches, pop. At end, the stack contains positions of all unmatched open brackets. For close brackets with no match, track them separately. fun unmatchedPositions(s: String): List<Int> { val stack = ArrayDeque<Int>(); val pairs = mapOf(')' to '(', ']' to '[', '}' to '{'); for ((i, ch) in s.withIndex()) { if (ch in "([{") stack.addLast(i) else if (ch in ")]}") { if (stack.isNotEmpty() && s[stack.last()] == pairs[ch]) stack.removeLast() else stack.addLast(i) } }; return stack.toList().sorted() }
Why does BFS use a Queue while DFS uses a Stack?
Easy▼
BFS visits all nodes at distance 1 before distance 2 — this "level by level" expansion requires FIFO (Queue). Nodes discovered first are visited first. DFS goes deep into one path before backtracking — this "last in, first out" exploration requires LIFO (Stack, or the implicit call stack in recursive DFS). Queue ensures breadth-first order. Stack ensures depth-first order. BFS guarantees shortest path in unweighted graphs; DFS doesn't.
