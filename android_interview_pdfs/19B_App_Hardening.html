1. Overview & Threat Model

Application hardening protects Android binaries against reverse engineering, runtime tampering (Frida, Xposed), unauthorized cloning, and compromised OS environments (rooted devices, Magisk/Zygisk).

OWASP MASVS (Mobile Application Security Verification Standard)
  • MASVS-STORAGE: Protection of sensitive data at rest.
  • MASVS-CRYPTO: Proper use of cryptography (hardware keys, modern algorithms).
  • MASVS-AUTH: Robust authentication and session management.
  • MASVS-NETWORK: Secure TLS communication and certificate validation.
  • MASVS-RESILIENCE: Obfuscation, anti-tampering, root detection, and device integrity verification.

2. How It Works Under the Hood

1. BiometricPrompt API

BiometricPrompt provides a uniform system UI for fingerprint, face, and iris authentication. Authenticators are classified by BiometricManager.Authenticators:

  • BIOMETRIC_STRONG: Hardware-backed TEE evaluation with <1% Spoof Acceptance Rate (SAR). Required for CryptoObject cryptographic signing.
  • BIOMETRIC_WEAK: Software or low-assurance biometrics. Cannot unlock Keystore CryptoObjects.
  • DEVICE_CREDENTIAL: Device PIN, pattern, or password.

2. Play Integrity API (Replaces SafetyNet)

Google Play Integrity verifies that your app binary is unmodified, running on a genuine certified Android device, and licensed from Google Play:

3. R8 Obfuscation & Component Hardening

1. R8 (Replaced ProGuard)

R8 performs 4 optimizations: Shrinking (removes unused code/classes), Optimization (inlining, removing dead code branches), Obfuscation (renames classes/fields/methods to a.b.c), and D8 Desugaring.

# proguard-rules.pro
-keepattributes *Annotation*, Signature, InnerClasses
-keepclassmembers enum * { *; }

# Keep data models used by Kotlin Serialization or Retrofit
-keep class com.example.model.** { *; }
-dontwarn okio.**

2. WebView Security Hardening

  • Never enable setAllowFileAccessFromFileURLs(true) or setAllowUniversalAccessFromFileURLs(true).
  • Only call setJavaScriptEnabled(true) when strictly necessary.
  • Validate all URLs in shouldOverrideUrlLoading() before navigating.
  • Prevent JavaScript interface reflection attacks on older Android versions.

4. Production Example (Biometric Auth with CryptoObject)
class BiometricAuthenticator(
    private val activity: FragmentActivity,
    private val onAuthenticated: (Cipher) -> Unit,
    private val onError: (String) -> Unit
) {
    fun authenticateWithCrypto(cipher: Cipher) {
        val executor = ContextCompat.getMainExecutor(activity)
        val prompt = BiometricPrompt(activity, executor, object : BiometricPrompt.AuthenticationCallback() {
            override fun onAuthenticationSucceeded(result: BiometricPrompt.AuthenticationResult) {
                result.cryptoObject?.cipher?.let(onAuthenticated)
                    ?: onError("CryptoObject was null")
            }
            override fun onAuthenticationError(errorCode: Int, errString: CharSequence) {
                onError(errString.toString())
            }
        })

        val promptInfo = BiometricPrompt.PromptInfo.Builder()
            .setTitle("Confirm Payment")
            .setSubtitle("Authenticate via biometric sensor")
            .setNegativeButtonText("Cancel")
            .setAllowedAuthenticators(BiometricManager.Authenticators.BIOMETRIC_STRONG)
            .build()

        prompt.authenticate(promptInfo, BiometricPrompt.CryptoObject(cipher))
    }
}

6. Pitfalls & Best Practices
Pitfall 1: Verifying Play Integrity Tokens on the Client Device

Decodes and checks Play Integrity tokens directly inside the Android app can be easily bypassed by attackers hooking the validation method using Frida. The token MUST be sent to your secure backend server and verified using Google's verification API.

Pitfall 2: Exported Components without android:exported="false"

Activities, Services, or Receivers with <intent-filter> are exported by default on older Android versions. Failing to set android:exported="false" allows malicious apps to launch private admin activities or trigger internal services directly.

Pitfall 3: Assuming Client-Side Anti-Tamper is 100% Unbreakable

Any code running on a device owned by an attacker can ultimately be reverse-engineered or hooked. High-value authorization decisions must always be made by the backend server.

7. Interview Framework

30-Second Elevator Pitch

"App hardening combines build-time optimizations and runtime integrity checks. R8 handles shrinking, dead code elimination, and symbol obfuscation. For authentication, BiometricPrompt paired with Keystore CryptoObject ensures cryptographic proof of user presence. To detect rooted or tampered devices, we use Google Play Integrity API with server-side token validation following OWASP MASVS standards."

2-Minute Deep Dive

"Client-side hardening is an exercise in defense-in-depth because client-side root checks (like RootBeer or file checks for /system/bin/su) can be bypassed by Magisk/Frida hooks. Therefore, true security relies on the Google Play Integrity API. The client requests an integrity token with a server nonce, and the backend verifies the signed JWT against Google's servers to confirm MEETS_STRONG_INTEGRITY and app licensing.

For authentication, BiometricPrompt enforces BIOMETRIC_STRONG with a Cipher CryptoObject. On the build side, R8 shrinks and obfuscates bytecode while stripping unused code. For component security, all non-public Android components explicitly declare android:exported='false', WebViews disable local file access, and sensitive activities enforce FLAG_SECURE."

Must-Mention Checklist

1
Play Integrity vs SafetyNet: Deprecated SafetyNet replaced by Play Integrity with server-side validation.
2
BiometricPrompt + CryptoObject: Hardware TEE authorization for sensitive crypto.
3
R8 Pipeline: Shrinking + Optimization + Obfuscation + Desugaring.
4
Root Detection Limitations: Why client checks fail and backend validation is mandatory.

9. Interview Questions (Self-Check)

Basic Questions

B1 — What is the difference between ProGuard and R8?
Easy▼
ProGuard was a separate standalone Java bytecode optimizer that ran before the Android dex compiler (D8). R8 is Google's all-in-one replacement that combines shrinking, optimization, obfuscation, and DEX compilation into a single, faster step while using the same ProGuard keep rules syntax.
B2 — What is the purpose of BiometricPrompt.CryptoObject?
Easy▼
A CryptoObject wraps a cryptographic Cipher, Signature, or Mac initialized with a hardware-backed Keystore key requiring biometric authentication. Successful authentication unlocks the cipher inside the secure hardware to complete sensitive operations (e.g. authorizing a money transfer).
B3 — What does android:exported="false" do?
Easy▼
It ensures that an Android component (Activity, Service, or BroadcastReceiver) can only be launched by components belonging to the same application or the Android system (UID match), preventing external third-party apps from launching private internal screens or services.

Intermediate Questions

I1 — Why are client-side root detection libraries (like RootBeer) insufficient on their own?
Medium▼
Client-side root detection checks for su binaries, specific packages, or build tags. Attackers using tools like Magisk (Zygisk), Shamiko, or Frida can easily hook and override these check functions to always return false. Client checks serve only as a minor deterrent and must be backed by remote attestation (Play Integrity API).
I2 — What are the 3 device integrity levels in Google Play Integrity API?
Medium▼
1. MEETS_BASIC_INTEGRITY: Device passes basic system checks (not a recognized malicious emulator).
2. MEETS_DEVICE_INTEGRITY: Device is a certified Android device running Google Play services and passes CTS tests.
3. MEETS_STRONG_INTEGRITY: Device has hardware-backed verified boot with a locked bootloader and uncompromised OS key.
I3 — What security precautions must be taken when using WebViews?
Medium▼
1. Disable file access: setAllowFileAccess(false).
2. Disable universal/file access from file URLs.
3. Enable JavaScript only when required.
4. Validate domains in shouldOverrideUrlLoading().
5. Never expose sensitive Native Java interfaces via addJavascriptInterface to untrusted web content.
I4 — What is OWASP MASVS and why is it important?
Medium▼
The Mobile Application Security Verification Standard (MASVS) by OWASP defines industry-standard security requirements across mobile architecture, data storage, cryptography, authentication, network communication, platform interaction, code quality, and resilience. It serves as the official security compliance baseline for banking and enterprise apps.

Senior & Scenario Questions

S1 — How do you design an end-to-end anti-tamper architecture for a banking transaction?
HardScenario▼
1. Client requests a cryptographic nonce from the backend server.
2. Client invokes Play Integrity API passing the nonce to generate a signed integrity token.
3. User authorizes transaction via BiometricPrompt with a TEE Keystore CryptoObject, signing transaction details.
4. Client transmits the signature, transaction payload, and Play Integrity token to backend.
5. Backend decrypts Play Integrity token directly with Google API to verify device and app authenticity, validates the nonce, and verifies the TEE signature before committing funds.
S2 — Why did your app crash with ClassNotFoundException only in the Release build?
HardScenario▼
In Release builds, R8 shrinking and obfuscation is active (minifyEnabled true). If a class (e.g., a Retrofit JSON model or dynamically loaded class via reflection) is not explicitly referenced in static bytecode, R8 strips it or renames its fields. Fix: Add appropriate @Keep annotations or configure -keep class com.example.model.** { *; } in proguard-rules.pro.
S3 — How do you prevent Tapjacking / Overlay attacks on sensitive payment buttons?
HardScenario▼
Set android:filterTouchesWhenObscured="true" on the sensitive Button / View in XML or call view.setFilterTouchesWhenObscured(true). In Jetpack Compose, inspect touch event flags or set View.setFilterTouchesWhenObscured(true) on the ComposeView. This discards motion events when another window (e.g. a malicious system overlay) obscures the screen.
